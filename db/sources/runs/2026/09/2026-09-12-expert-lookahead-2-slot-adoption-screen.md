**Diagnosis that drove the retry.** The decomposition of the staging screens (recorded in the native-screens run) showed the demand-IO clock following the read-cost model in every arm while the non-IO part of decode grew 38% to 111%; at stride 2 the growth (28 s) had no host counter behind it. Reading the adoption path against the demand path: a demand record is read into a per-batch staging buffer and scattered once; an adopted speculative record was read into nine freshly allocated per-ticket buffers, wrapped as nine arrays with finalizers, concatenated with its batch (a second GPU copy) and then scattered, and 45% of tickets expired after paying all of that for nothing. The retry removes that path: **slot adoption** reserves the CLOCK victim slot when the ticket is issued (the slot's key is evicted then and the slot leaves every victim scan), the worker writes the record into that slot's pool memory, and adoption is a map insert with no copy, no allocation and no graph work. Unused reservations return through a lock-protected queue drained on the model thread and feed a free-slot list that the next reservation takes before evicting anything; a reservation whose pool piece base pointers moved is refused; the byte cap is replaced by a reservation cap (`SLOTSTREAM_EXPERT_PREFETCH_SLOT_CAP`, 64). Control: `SLOTSTREAM_EXPERT_PREFETCH_ADOPT=slot` (default `staging`, the shipped mechanism).

**Host stall.** At 10:00:44 local the on arm of the top-6 pilot printed `engine ready` and never produced a token; after 42 minutes a process sample showed the model thread waiting on a `concurrentPerform` in `ExpertStore.readRunsChecked` (the prefill sweep's staging read) whose one worker was inside a `pread` that had not returned, every other thread idle, 0% CPU, 160 MB resident. That arm had run its warmup request with slot-mode prefetch before the stall; the stalled read itself was an ordinary staging read. The process was killed and remains in the kernel's exiting state (`E`, no resident memory) holding the per-user model lock; the next engine start (candidate 6's parity run) blocked in an uninterruptible wait (`U`) at startup before opening any model file and is now in the same state. Time Machine was idle; no kernel message was found. The bench gained a 1,200 s arm timeout (a stalled arm is killed, recorded as `stalled`, and its pair is ineligible) and a lock fallback that is taken only when the default lock is held and no live model process exists (`SLOTSTREAM_MODEL_LOCK_PATH`, honored by the engine, the bench and the capture preflight). Candidate 7 removes the one kernel-level novelty of slot adoption, the uncached file read straight into GPU-shared pool memory, as a precaution; the cause is unproven either way. No model process can start until the host restarts. `w9/run-after-reboot.sh` then runs the T0 checks, the six-request parity of candidate 7 at the screen setting, a one-round pilot and the B0 cohort (`w9/plan-b0-slot-s2thr-l16/plan-b0.json` `df6334ab6c184398…`: six sealed families, two prompts each, three rounds, 512 outputs, current deployment against slot prefetch with the reserve charged).
